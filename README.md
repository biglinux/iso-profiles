# BigLinux iso-profiles

Package lists and overlay files that describe a BigLinux ISO. This repository
does not build ISOs — `buildiso` reads `biglinux/<edition>/` from it.

## The one rule

```
sources/     <- edit this
biglinux/    <- generated by CI, never edit
```

`biglinux/` is rebuilt from scratch on every push and weekly, then committed by a
bot. An edit there is silently reverted on the next run. It stays in git because
the ISO builders read it directly — see [`biglinux/README.md`](biglinux/README.md).

## Layout

```
sources/
├── common/                    applies to every edition
│   ├── Root-add  Root-remove    installed system packages
│   ├── Live-add  Live-remove    live session only
│   ├── Mhwd-add  Mhwd-remove    driver packages
│   ├── profile.conf             hostname, live user, services
│   ├── user-repos.conf          BigLinux pacman repositories
│   └── overlays/root/  desktop/  live/     files shipped as-is
└── editions/
    ├── kde/                   Desktop-add + special-commands.sh
    └── xivastudio/            same, plus its own trims
```

Package lists start as Manjaro's: the CI takes upstream's list, drops every
`*-remove` entry, appends every `*-add` entry, and writes the result into
`biglinux/<edition>/`. That way a Manjaro rename or split is absorbed weekly
without anyone editing a 460-line file.

`Packages-Desktop` works differently: it has no Manjaro base of its own, so
`Desktop-add` is written over it rather than appended. It is not the whole list,
though — `editions/kde/special-commands.sh` then grafts four sections copied
verbatim from Manjaro's own KDE profile (`## Printing`, `## Xorg Server and
Graphics`, `## Xorg Input Drivers`, `## Misc`), which is where `xorg-server` and
the printing stack come from. Look there before concluding a package is missing.

## What to edit

Paths relative to `sources/`.

| Goal | Edit |
|---|---|
| Add a package to every edition | `common/Root-add` |
| Drop a Manjaro package from every edition | `common/Root-remove` |
| Change a KDE desktop package | `editions/kde/Desktop-add` |
| Change a live-session-only package | `common/Live-add` / `common/Live-remove` |
| Change a driver package | `common/Mhwd-add` / `common/Mhwd-remove` |
| Ship a file in the installed system | `common/overlays/root/` |
| Ship a file only in the live session | `common/overlays/live/` |
| Add an edition | new dir in `editions/` with `Desktop-add`, then list it in `editions` in the workflow |

Push, wait for the bot commit, then build an ISO.

## Three things that surprise people

**Removal matches a substring.** `*-remove` feeds `grep -vF -f`, so an entry
drops every line *containing* it. That is deliberate: `libva-mesa` is the prefix
that removes Manjaro's `libva-mesa-driver`. It also means `micro` would remove
`libmicrohttpd` — use the longest prefix that still catches what you want.

**`kde` is built before `xivastudio`.** `editions/xivastudio/special-commands.sh`
appends the generated KDE desktop list to its own, so the order in the workflow's
`editions` variable matters. Keep it.

**`KERNEL` is a placeholder, not a package.** `buildiso -k linux618` expands
`KERNEL-nvidia-580xx` into `linux618-nvidia-580xx`. Leave it as `KERNEL`.

## Reference

`repo_info` in the root is not documentation: `manjaro-tools` finds a profile
repository by searching for that file.

`root-overlay/` lands in the installed system, `desktop-overlay/` in the desktop
image, `live-overlay/` only in the live session. The CI renames
`common/overlays/root/` to `root-overlay/` because those are the names
`manjaro-tools` expects.

Repositories come from `user-repos.conf`. A profile-level `pacman-default.conf`
is never read, which is why this repository does not ship one.
